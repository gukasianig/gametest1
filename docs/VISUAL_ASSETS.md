# Визуальные ассеты: что есть и что подготовить

Обновлено: 2 ноября 2026. Рабочий каталог для будущей генерации и подключения арта. Основание: файлы Assets, сцена SampleScene, код создания объектов и просмотр ArenaIcons.png. Свежая визуальная проверка игры не проводилась. Все описания будущего оформления ниже — предложения, а не уже созданные ресурсы или утверждённая владельцем художественная концепция.

## Как пользоваться

- Перед генерацией читать этот файл и проверять соответствующий ассет/код: состояние может измениться.
- Статусы: **есть** — файл или процедурное представление найдено; **заглушка** — примитив вместо окончательной модели; **предложено** — ещё не создано. Наличие файла не означает визуальную приёмку в игре.
- Для заказа можно сослаться на ID, например «подготовь VA01» или «сгенерируй концепт VA05». ID сохранять при обновлении.
- Генерация картинки даёт иллюстрацию, текстуру или референс. Для игровых 3D-объектов отдельно нужны модель, UV, материалы, при необходимости риг и анимации. PNG с нарисованной моделью не заменяет FBX.
- После создания записать путь, версию, источник/инструмент, дату, статус импорта и фактическую проверку. При замене сохранять существующие .meta/GUID. Будущие папки ниже пока не созданы.

## Предлагаемое художественное направление

**Индустриальная научно-фантастическая арена, стилизованные компактные формы, читаемые сверху.** Основание — существующая арена, бирюзовый UI и металлические предметы атласа. Предложение: герой — оператор в броне, враги — неисправные промышленные боевые машины. Такая тема объясняет контейнеры, генератор, дрон и кристаллы, но пока не закреплена сюжетом.

- Мир: матовый графит/сине-серая сталь, редкие потёртости; окружение менее контрастное, чем персонажи. Без фотореалистичной грязи на всей поверхности.
- Герой/дружественные устройства: бирюзовый и светлая броня; XP — голубой кристалл. Отличать опытом форму, размер и расположение, а не только похожий цвет.
- Враги: сохранить нынешние ролевые цвета как акценты, добавить разные силуэты и знак сверху. У Healer использовать технический плюс, без эмблем реальных организаций.
- Опасности: чёткий контур и направление, оранжевый/красный акцент. Декоративные кольца не должны выглядеть как круг атаки.
- UI: сохранить рисованную объёмность текущих иконок; в мире проще формы и материалы. Согласовать мотивы, не требовать одинаковой детализации иконки и далёкой 3D-модели.
- Камера в сохранённой сцене перспективная, FOV 60, offset (0,18,-6), возможен зум. Референсы делать с видом сверху под наклоном; проверять реальные игровые размеры, а не только красивый боковой ракурс.
- Мелкий орнамент, тонкие антенны и надписи не должны нести единственную информацию о роли.

Для листа видов после выбора концепта:

## Требования к подготовке и приёмке

Предлагаемые пути: `Assets/Art/Characters/`, `Enemies/`, `Weapons/`, `Environment/`, `VFX/`, `UI/`; концепты хранить вне импортируемых игровых ресурсов, например `docs/art-references/`. Существующий атлас пока оставлять по текущему Resources-пути.

1. Сначала выбрать один концепт VA01 и один массовый враг VA02, проверить их совместимость с текущими иконками. После этого делать остальные роли в том же языке форм. Модели и генерацию не начинать автоматически по наличию списка.
2. Для 3D: масштаб 1 Unity unit = 1 м, низ у модели на полу, вперёд +Z/вверх +Y после импорта; для оружия согласовать локальные оси хвата. Отдельный визуальный дочерний объект предпочтителен для сохранения существующих игровых компонентов/коллайдеров.
3. Начальный ориентир детализации, ещё не профилированный: обычный враг 1–3 тыс. треугольников, герой 3–6 тыс., босс 5–10 тыс.; общий материал/атлас где возможно. Это бюджет для обсуждения, не измеренная гарантия производительности.
4. Unity 2022.3.62f3, URP. Материалы URP/Lit, для простых VFX Unlit; проверить отсутствие розового шейдера, корректную альфу и края спрайтов. UI не должен иметь запечённый тёмный фон.
5. Анимации движения сначала in-place: код уже управляет положением. Подключение Animator и событий атаки — отдельная реализация; анимация не меняет время нанесения урона сама по себе.
6. Статически проверить имена, пути, GUID, настройки импорта, нарезку/порядок иконок. После завершения связанного набора — один короткий совмещённый Play-прогон с прямыми зависимостями, как требует AGENTS.md.
7. В игре проверить читаемость сверху при обычном зуме и отдалении, различие ролей в оттенках серого, контакт с полом, соответствие коллайдера, выстрела и предупреждения урона. В толпе арт не перекрывает HP/XP и не создаёт лишнего свечения. Не считать просмотр концепта или компиляцию такой проверкой.
8. Для UI проверить 64×64, тёмный/светлый фон, узкое окно и текущие карточки. Известное пересечение заголовка улучшений с таймером исправляется в раскладке, новая картинка его не устраняет.
9. Зафиксировать происхождение и разрешения на использование новых ресурсов без токенов/персональных данных; пункт Q07 пока не закрыт. При необходимости смены темы сначала скорректировать описания здесь.
